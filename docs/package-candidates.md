# Pi package candidates

Candidate Pi packages from https://pi.dev/packages. This is a review list, not an install list.

Policy:

- Do not auto-install packages from this file.
- Prefer personally reviewed, pinned packages.
- Prefer extensions that improve security/DX or support the planned workflows.
- Avoid broad overlapping orchestration/memory systems unless they replace a planned in-house component.

## Review order

1. `@gotgenes/pi-permission-system` — security foundation.
2. Subagent substrates: `pi-subagents`, `@tintinweb/pi-subagents`, `@arhen/pi-core-subagent`, Pi official `subagent/` example — see `docs/subagent-package-comparison.md`.
3. `@plannotator/pi-extension` — decide whether plan approval/annotation should gate autonomous execution.
4. Loop/monitor candidates: `@trevonistrevon/pi-loop`, `pi-autoresearch`, `@agimon-ai/doompi-loop` — see `docs/loop-subagent-extension-status.md`.
5. `pi-background-tasks` — decide whether it helps `agent-pr`/parallel tasks.
6. `pi-lens` and `@ff-labs/pi-fff` — DX without changing agent behavior too much.
7. `@dietrichgebert/ponytail` — review as a minimalism/YAGNI skill after workflow substrate decisions.
8. Memory candidates: `pi-hermes-memory`, `@amaster.ai/pi-memory-mem0` — decide after memory/Obsidian grilling.
9. `pi-web-access` / `pi-mcp-adapter` — only if specific integrations are needed.
10. `pi-fabric` — defer unless it clearly replaces multiple planned pieces.
